## Утверждённые числовые параметры (06.11.2026; только GDD)

| Контейнер | Слотов | MaxWeight содержимого | Собственная масса |
|---|---:|---:|---:|
| Core | 12 | 15 кг | Не применяется |
| Малый Bag | 8 | 15 кг | 1,5 кг |
| Средний Bag | 12 | 25 кг | 3 кг |
| Большой Bag | 18 | 40 кг | 5 кг |

Мягкий порог комфортной общей массы персонажа: **35 кг**. Собственная масса рюкзака учитывается в общей нагрузке персонажа, но не расходует MaxWeight самого Bag. Значения утверждены владельцем 06.11.2026; конкретные штрафы/кривая перегруза остаются открыты. Это проектирование, не изменение A05–A12/Blueprint.

## Нормативный маршрут BP-D04

1. Валидация A15: живой/доступный предмет, корректные range/LoS/focus, состояние игрока, Stack и блокировка повторного вызова.
2. Симуляция Exact всех Q единиц в Core. Если подходит, commit в Core; Bag не меняется.
3. Только при SlotsFull или WeightLimit Core: проверить валидный **надетый** Bag; снятый в мир рюкзак никогда не является автоматическим приёмником.
4. Симуляция Exact Q единиц в Bag. Если подходит, commit в Bag; Core не меняется.
5. На этапе S1, если Core и Bag по отдельности не принимают Q, отказ; WorldPickup остаётся, два inventory неизменны.
6. После отдельной реализации S2/P1, только при обоих capacity-отказах: предварительно просчитать Core+Bag и либо единовременно commit **все Q** с удалением WorldPickup, либо отказаться без изменения трёх состояний. S3 не разрешён.
7. Любая неёмкостная ошибка, stale ownership/equipment, смерть или изменение Revision до commit → отказ; не обходить посредством Bag.

## Гарантии интеграции

- A09/A10/A11: сохранить MaxWeight, MaxStack, совместимость Durability, GUID, Revision, mutation guards, события и строгие коды ошибок. A11 TryTransferExact сам по себе не является общим commit Core+Bag+WorldPickup.
- A15: ровно один итог на pickup, отсутствие дублей от повторного E, уничтожения WorldPickup только после успешной операции.
- A16/A17: UI сообщает результат, но не владеет предметами, не маршрутизирует игровой pickup и не меняет Slots напрямую.
- BP-D03: смена/снятие рюкзака между подготовкой и commit делает кандидат недействительным; новая попытка должна брать актуальный snapshot.
- DEATH01: завершённый до DeathStarted pickup становится носимым имуществом; после DeathStarted новый pickup блокируется.
- A36–A40: только завершённые состояния попадают в сохранение; новые типы сущностей требуют отдельной версии DTO/миграции до реализации.
- Никаких новых штрафов за вес, вложенных рюкзаков, правил переноса пустых рюкзаков и UI этим решением не утверждено.

## Проверки при будущей реализации (все NOT RUN)

Core only, fallback Bag, нет экипированного Bag, оба capacity-full (S1 отказ / S2 atomic), Core Busy/NotReady, умерший игрок, снятие Bag в процессе, повторное E, duplicate GUID, stale Revision, float weight tolerance, load на границе операции, полный rollback.
