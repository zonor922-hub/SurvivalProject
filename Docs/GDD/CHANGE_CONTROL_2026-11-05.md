# CHANGE-CONTROL-01 — межсистемное согласование механик

Владелец подтвердил 05.11.2026: при изменении механики обязательно выявлять и разрешать противоречия во всех затронутых механиках, документах, Save DTO, UI, runtime-контрактах и тестах. **Утверждённая идея ≠ реализовано ≠ проверено**. Утверждение проектного решения не разрешает автоматически менять Blueprint.

## Реестр конфликтов и будущих работ

| Код | Система | Фактическая база | Новая целевая норма | Что сделать |
|---|---|---|---|---|
| C-001 | A23/respawn, GDD | Inventory сохраняется в PlayerState | При смерти теряется всё носимое имущество, его можно вернуть до истечения | Отдельное ТЗ/PR, новая приемка, rollback, UI lifecycle |
| C-002 | A15 | TryAddExact в один Core | BP-D04 Core→EquippedBag и этап S2/P1 | Координатор, guards, единый commit, regression |
| C-003 | A36–A40 | Save v1 с inventories/DTO, без полноценного мобильного Bag и death-cache TTL | Переносимые контейнеры + таймер потери | Версионирование/миграция; не менять v1 без решения |
| C-004 | A09/A11 | Жёсткий MaxWeight, точные transfer | Дополнительный мягкий порог персонажа | Не ослаблять MaxWeight, тесты нагрузки и GUID |
| C-005 | A16/A17, A24 | HUD/inventory и плавание по прежним контрактам | Новые pickup results, экипировка, штрафы нагрузки | UI/плавание менять только после утверждения деталей |

## Рабочий порядок

1. Change Request и точная запись утверждённой нормы.
2. Dependency/impact analysis и отмеченные противоречия.
3. Согласованный design spec, разграничение фактов реализации и новой цели.
4. План runtime-патча, версии DTO, миграции, отката и тестов.
5. Отдельное разрешение на изменения Blueprint.
6. Регрессия на чистом HEAD с явным статусом PASS/FAIL/NOT RUN.
7. PR review и merge. Исторические проверки не переписывать задним числом.

**В этой документационной ветке:** только текст. Ни Blueprint, ни карты, ни runtime assets не меняются.
