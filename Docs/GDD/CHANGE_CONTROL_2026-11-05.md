# CHANGE-CONTROL-01 — межсистемное согласование механик

Владелец подтвердил 05.11.2026: при изменении механики обязательно выявлять и разрешать противоречия во всех затронутых механиках, документах, Save DTO, UI, runtime-контрактах и тестах. **Утверждённая идея ≠ реализовано ≠ проверено**. Утверждение проектного решения не разрешает автоматически менять Blueprint.

## Рабочий порядок

1. Change Request и точная запись утверждённой нормы.
2. Dependency/impact analysis и отмеченные противоречия.
3. Согласованный design spec, разграничение фактов реализации и новой цели.
4. План runtime-патча, версии DTO, миграции, отката и тестов.
5. Отдельное разрешение на изменения Blueprint.
6. Регрессия на чистом HEAD с явным статусом PASS/FAIL/NOT RUN.
7. PR review и merge. Исторические проверки не переписывать задним числом.

**В этой документационной ветке:** только текст. Ни Blueprint, ни карты, ни runtime assets не меняются.

## Правило TIME-D01 (05.11.2026)

**Принято:** в обычной игре календарь идёт фиксированным темпом; нет ручной перемотки, режима ×2/×4 и кнопки ожидания. Только сон вправе сдвигать мировые часы вперёд. Это должно соблюдаться во всех будущих механиках времени, не только DEATH01.

**Остаются открыты:** выбор B1 в качестве окончательной политики DEATH-D05, пробные 60 реальных минут/игровые сутки и 3 игровых дня DEATH-D06, срок при повторной смерти, форма потерянного груза. Формальный переход к реализации и тесты не выполнены.
