## Замечания и решение

1. **A17-F1 — снят уточнением объёма:** владелец подтвердил, что Split/Merge и Revision не входят в исходный MVP. Backlog теперь содержит отдельную A17.1. Их отсутствие в виджетах не блокирует A17 MVP и не скрывается: команды не реализованы и не являются критерием приёмки MVP.
2. **A17-F2 — ограничение MVP:** RefreshInventory вызывается при открытии экрана; подписки OnInventoryChanged в экспортированных графах виджетов/контроллера не найдены. Для read-only MVP без изменяющих инвентарь действий внутри окна это допустимый жизненный цикл. Обновление при внешней операции во время открытого окна не доказано; проверить/реализовать при появлении такого потока либо в A17.1.
3. **A17-F3 — отдельная lifecycle зависимость:** InventorySource задаётся при первом создании кэшированного виджета. Перепривязка при замене PlayerState/источника не подтверждена; задача A19 зависит от A17 MVP/A17.1/A18 и должна закрыть сценарии смены Pawn/PlayerState. Для A17 MVP смена Pawn/PlayerState в критерии не входит.
4. Самостоятельные UI-контрактные/PIE-тесты A17, A12-регрессия в этом аудите, cook/package, multiplayer и визуальная QA — **NOT RUN**. Компиляция не заменяет эти результаты. Независимый аудит ограничен доступным Editor API; прямой source-level аудит бинарных пакетов не заявляется.

**Вердикт: A17 MVP завершила ручную приёмку 10/10; SHA всех тестировавшихся целей и зависимостей совпали до/после PIE.** Split/Merge и stale Revision остаются только в A17.1.
