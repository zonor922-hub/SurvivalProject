# План реализации: 44 небольшие задачи

**A01–A04 выполнены** — [проверка в редакторе](05_A01_EDITOR_AUDIT.md), [резервная копия и Git/LFS](06_A02_BACKUP_AND_VERSIONING.md). [Основные классы A03](07_A03_GAMEPLAY_BOOTSTRAP.md). [Карта и журнал A04](08_A04_SYSTEMS_TEST_MAP.md). A05–A44 имеют статус **не начата**. Игровые механики по этому плану ещё не реализованы.

Одна задача — один проверяемый результат и отдельный commit/снимок. Ориентир размера: одна рабочая итерация разработчика; если задача не помещается, разделить её, сохранив ID родителя и зависимости. Сроки не оценивались: графы и состояние сборки ещё требуют проверки.

Номера задают удобный порядок; выполнять задачу можно только после всех её зависимостей. A36 полезно выполнить сразу после A05, до написания сериализации остальных систем. Дополнительные зависимости между картой и плаванием не должны блокировать изолированные inventory-тесты.

Общие критерии каждой задачи: затронутые Blueprints компилируются; нет новых Accessed None; существует воспроизводимый сценарий проверки; изменения ограничены заявленными файлами; результат и ограничения внесены в журнал. Снимок экрана сам по себе не подтверждает корректность данных.

## Инвентарь

### A08 — Реализовать состояние и чтение inventory

- **Зависимости:** A06.
- **Результат:** BPC_Inventory на PlayerState, private Slots/Revision, GetSnapshot и расчёт веса, тестовая фикстура 4 слота/10 веса.
- **Проверка:** изменение полученной UI-копии не меняет компонент; пустой inventory имеет вес 0; два одинаковых init не сбрасывают существующие предметы.

### A09 — Реализовать добавление и удаление целиком

- **Зависимости:** A08.
- **Результат:** TryAddExact/TryRemoveExact, симуляция на копии, mutation guard и OnInventoryChanged после commit.
- **Проверка:** добавить 21 wood → стеки 20+1 при подходящей вместимости; убрать 2 из распределённых стеков; qty 0/−1, неизвестный ID, превышение веса/слотов оставляют snapshot и revision прежними. На успех — одно событие.

### A10 — Реализовать разделение и объединение

- **Зависимости:** A09.
- **Результат:** TrySplit/TryMerge с устойчивыми StackId и адресацией свободного слота.
- **Проверка:** 10 wood разделяются 4+6 без изменения веса; merge не превышает MaxStack; разные ItemId/прочность не объединяются; split без свободного слота ничего не меняет; GUID не дублируются.

### A11 — Реализовать перенос между inventories

- **Зависимости:** A09, A10.
- **Результат:** TryTransferExact с проверкой двух revisions и единым commit двух копий.
- **Проверка:** перенос 3 единиц уменьшает источник и увеличивает приёмник на 3; полный приёмник, устаревшая revision и source=destination не теряют/не дублируют предметы; callbacks не видят промежуточное состояние.

### A12 — Закрепить инварианты inventory тестами

- **Зависимости:** A04, A11.
- **Результат:** воспроизводимый набор Blueprint functional tests или эквивалентный тестовый harness с assert по snapshots.
- **Проверка:** набор покрывает обе границы веса, заполненные слоты, многостековое удаление, split/merge, transfer, stale revision; повторить с одинаковыми данными три раза. Проверять баланс количеств, не детали графа реализации.

### A19 — Закрепить lifecycle игрока

- **Зависимости:** A14, A20.

### A22 — Реализовать употребление предмета

- **Зависимости:** A09, A17, A20.

- **Проверка:** одна ягода уменьшает quantity на 1 и увеличивает Hunger на заданное число с clamp; при полном Hunger NoEffect без списания; неизвестный effect/смерть/повторная команда со старой revision не расходуют предмет.

### A23 — Реализовать смерть и respawn

- **Зависимости:** A19, A20, A21.
- **Результат:** одно событие смерти, блокировка действий, respawn через GameMode; inventory сохраняется, survival сбрасывается по профилю.

### A24 — Проверить и исправить плавание изолированно

- **Проверка:** искусственно неудачная запись оставляет старое сохранение; повреждение нового слота восстанавливает предыдущий; неверная новая schema не перезаписывается; success показывается после фактического завершения записи.

### A39 — Реализовать восстановление мира

- **Зависимости:** A38.
- **Результат:** последовательность load из архитектуры с отключёнными timers/loot до завершения; resolve GUID links и повторное подключение UI.
- **Проверка:** подобранный authored pickup не возвращается, динамический build не удваивается, storage contents и inventory совпадают; player transform/показатели восстановлены; два load подряд дают одинаковое количество сущностей.

### A40 — Проверить persistence и совместимость

- **Зависимости:** A39.
- **Результат:** save/load fixtures и тест кругового восстановления; обработка отсутствующего ItemId/BuildId и некорректных support links.
- **Проверка:** изменить файл каталога в тестовой копии → понятный отказ без потери старого save; данные до/после загрузки совпадают по ID/quantity/state; трансформ с оговорённым допуском 1 cm/0.1°; тест проходит после перезапуска приложения.

## Интеграция и передача

### A41 — Подключить вертикальный срез к карте природы

- **Зависимости:** A24, A27, A28, A35, A40.
- **Результат:** нужный GameMode override природы, маленькая стартовая зона с несколькими ресурсами, no-build zone озера; исходное окружение сохранено.
- **Проверка:** от PlayerStart пройти цепочку pickup→craft→build→storage→consume→save/load; при плавании нельзя ошибочно строить на воде; трава/камни/деревья не заменены массово gameplay actors.

### A42 — Настроить стартовую карту и проверить Windows build

- **Зависимости:** A07, A41.
- **Результат:** EditorStartupMap/GameDefaultMap намеренно указывают рабочую Survival-карту; релизный cook-list без backup/demo; проверенная Water dependency и все soft assets.
- **Проверка:** чистый запуск Windows Development build открывает природу и повторяет короткую цепочку A41; нет missing package/classes; сохранение переживает перезапуск; vendor backup-карты не попадают в cook случайно.

### A43 — Провести регрессию и замер стоимости механик

- **Зависимости:** A12, A35, A40, A42.
- **Результат:** таблица pass/fail и CPU/GPU frame time относительно baseline, actor/timer counts, список оставшихся проблем по приоритетам.
- **Проверка:** все критические проверки inventory/placement/save проходят; 10 открытий UI и 3 respawn не увеличивают число callbacks/timers; inventory не тикает на каждом предмете; замер повторён на том же железе/разрешении/камере. Просадку описать числами, не обещать FPS без измерения.

### A44 — Подготовить пакет передачи

- **Зависимости:** A43.
- **Результат:** обновлённая документация фактической архитектуры, список assets/config changes, инструкция запуска/rollback, тестовые saves, известные ограничения и следующий backlog.
- **Проверка:** другой разработчик по инструкции открывает нужный проект и карту, повторяет вертикальный срез, находит подтверждение каждого теста; нереализованные механики явно помечены. Версия Blueprint/API из плана заменена фактической только там, где проверена.
