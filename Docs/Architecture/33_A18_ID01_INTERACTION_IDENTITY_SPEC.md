## 1. Решение и границы утверждения

Владелец выбрал контракт из девяти пунктов в запросе A18-ID01: новый getter в BPI_Interactable, стабильные WorldEntityId, пустой ID только для read-only подсказки, интерфейсный HUD и сохранение A15. Этот документ конкретизирует выбранные правила для утверждения **версии 1.0**. Выбор направления не объявляется утверждением технических деталей ниже.

Цель: подсказка для любого Actor с BPI_Interactable без обязательного наследования от BP_WorldPickup; безопасная идентичность цели будущих команд. Игрок видит прежний prompt/disabled reason; поиск focus сам не меняет inventory.

Зависимости: [A13](23_A13_INTERACTION_FOCUS.md), [A15](25_A15_WORLD_PICKUP.md), [A16](28_A16_INTERACTION_HUD.md), [A17/A17.1](30_A17_1_LOCAL_STATUS_AND_PUBLICATION.md); ограничения внешнего доступа из [INVENTORY-UX](../GDD/INVENTORY_UX_DECISIONS_2026-11-06.md), [baseline gate](32_BASELINE_GATE_DECISION_2026-11-07.md) и [Design First Policy](../Development/01_DESIGN_FIRST_POLICY.md). A11 остаётся неизменной зависимостью будущего переноса; ID01 не реализует перенос.

В поставку после утверждения входят getter, его реализации для pickup/storage, рефакторинг HUD, проверка идентичности и дубликатов, назначение ID конкретным authored storage в тестовой карте и целевые проверки. **Open, двухпанельный UI, session token, transfer, стартовое наполнение и полноценный Save/Load не входят.** Новая универсальная маршрутизация E также не входит: существующий pickup-путь сохраняется. ID01 не даёт сундуку работающего Open; включённая подсказка существующего ручного прототипа не служит доказательством доступности команды.

## 2. Установленные причины и достоверность

В предыдущем read-only аудите текущих графов через Unreal MCP установлено:

- HandleInteractionFocusChanged: NewFocus -> Cast To BP_WorldPickup -> GetInteractionOptions; Cast Failed -> HideFocusInfo. TargetId берётся из pickup.WorldEntityId.
- Вручную добавленные Does Object Implement Interface и Branch не подключены к exec. Это незавершённая пользовательская работа, а не готовое исправление.
- HandleWorldPickupRequest имеет отдельный cast и действие Pickup; BP_WorldPickup.ExecuteInteraction содержит проверки Context, Consumed и PickupInProgress. Этот cast нельзя удалять вместе с HUD-cast.
- BPC_Interaction.UpdateFocus проверяет BPI, range, LoS и валидность Actor. Фактический HitActor сундука не установлен; дополнительный дефект trace не доказан.
- Storage.GetInteractionOptions возвращает Open/Open Chest/Enabled=True. ExecuteInteraction сразу возвращает неуспех. В прочитанном списке переменных storage нет WorldEntityId.

В ходе подготовки документа вновь прочитаны через MCP BP_WorldPickup.UserConstructionScript (пустая функция) и EventGraph (пустой DSL). Это не аудит всех источников назначения ID и не сравнение дискового/несохранённого графов. Новые compile/PIE PASS не заявляются. Сведения пользователя о работающем Pickup и параметрах StorageInventory не заменяют будущую регрессию.

## 3. Интерфейс и семантика ID

В существующий BPI_Interactable добавляется синхронная функция:

| Элемент | Контракт |
|---|---|
| Имя | GetInteractionTargetId |
| Входы | Нет, кроме целевого объекта интерфейсного вызова |
| TargetId | Guid |
| HasStableId | Boolean |
| Побочные эффекты | Запрещены: генерация/присваивание ID, inventory-команды, создание объектов, dispatchers, изменение focus/UI |

GetInteractionOptions(Context) и ExecuteInteraction(Context, ActionId), структуры FInteractionContext/FInteractionResult сохраняют сигнатуры. Getter не требует latent-вызовов или новой базовой Actor-иерархии. Все фактические implementers выявляются до изменения BPI, затем компилируются; им нельзя автоматически приписывать стабильность.

`HasStableId=True` означает: getter вернул непустой WorldEntityId, назначенный по жизненному циклу раздела 4. Флаг **не** удостоверяет уникальность, разрешение доступа, authority или валидность Context. Каждый вызывающий дополнительно проверяет IsValidGuid(TargetId). Противоречивый ответ True + пустой GUID считается отсутствием пригодного ID.

При отсутствии стабильного ID корректный ответ: пустой Guid и False. Для HUD неподтверждённый ID также заменяется пустым Guid. Две цели с одним GUID могут обе вернуть True: конфликт выявляет отдельная проверка, а не getter с побочными эффектами.

| Идентификатор | Владелец/назначение |
|---|---|
| WorldEntityId / Interaction TargetId | Идентичность мировой сущности Actor |
| InventoryId | Идентичность inventory из существующего контракта |
| StackId | Идентичность стека из существующего контракта |

Нельзя подставлять InventoryId, StackId, имя/путь Actor, индекс массива, hash transform либо новый временный GUID вместо отсутствующего WorldEntityId.

## 4. Назначение и жизненный цикл

- **Authored storage:** WorldEntityId типа Guid, Instance Editable; default класса — пустой. При подготовке конкретного уровня назначается новый GUID конкретному экземпляру и сохраняется в карте. Нет автоматической генерации в Construction Script, BeginPlay, getter или HUD. Существующий валидный ID не заменяется при сохранении, перемещении Actor или повторном PIE.
- **Дублирование authored Actor:** скопированный ID считается конфликтом. До приёмки уровня владельцу нового экземпляра явно назначается новый GUID; инструмент не выбирает молча, какой из существующих объектов переименовать. Два уже используемых ID требуют ручного решения до изменения сохранений.
- **Pickup:** getter возвращает существующий WorldEntityId и результат его валидности. Не переименовывать существующие pickup ID, не менять Stack или A15 guards/ExecuteInteraction. Перед реализацией проверить реальные источники ID у authored и dynamic pickup. Если обнаружена перегенерация при BeginPlay или отсутствует безопасный путь назначения, зафиксировать CHANGE REQUIRED и остановить затронутую реализацию, не переписывать A15 молча.
- **Dynamic:** создающий объект код назначает уникальный ID один раз до предоставления объекта взаимодействиям. Если используется deferred spawn, ID передаётся до завершения spawn/BeginPlay. Обычный spawn без безопасной инициализации не получает автоматического fallback в BeginPlay. Новые production-spawner и система drop не создаются в ID01.
- **Load:** загрузчик восстанавливает сохранённый ID до допуска к взаимодействиям. Отсутствующий, повреждённый или конфликтующий ID не исправляется новым GUID. Save DTO и загрузчик не реализуются в ID01; этот сценарий проверяется тестовой инициализацией с заданным ID, а не объявляется настоящим Save/Load PASS.
- **BeginPlay/EndPlay, потеря focus, закрытие UI:** не назначают и не меняют ID. Уничтоженный Actor не является пригодной целью даже при сохранённой копии его GUID.

## 5. Проверка уникальности без изменения A36 v1

Предлагается небольшая библиотека `BPFL_InteractionIdentity` с read-only функцией `ValidateInteractionTargetIdentity(TargetActor, ExpectedTargetId) -> Valid, FailureReason: Name`. Она проверяет только идентичность и не заменяет range/LoS, authority и правила конкретного действия.

Алгоритм для изменяющей команды/тестового вызова:

1. Проверить живой TargetActor, BPI_Interactable и непустой ExpectedTargetId.
2. Прочитать getter цели; потребовать HasStableId, IsValidGuid и точное совпадение с ExpectedTargetId.
3. В текущем мире цели получить все живые Actor с BPI_Interactable и прочитать их getter. Если другой Actor возвращает такой же непустой TargetId, отказать. При сравнении дубликата не полагаться на HasStableId другого Actor: непустое совпадение всё равно конфликт.
4. Перед возвратом успеха повторно проверить живую исходную цель и неизменность её ID. Функция синхронная, не сохраняет список или положительный результат между командами.

Имена причин принадлежат только этой проверке, не расширяют enum ошибок A11: `InvalidTarget`, `MissingStableId`, `TargetIdMismatch`, `DuplicateTargetId`, `IdentityCheckUnavailable`; успех — `None`. При невозможности достоверно выполнить проверку возвращается отказ. Getter по контракту не должен менять мир при обходе.

Отдельный read-only editor-аудит `scripts/a18_id01_validate_ids.py`, выполняемый через MCP/Editor API после утверждения, формирует группы GUID -> пути Actor в загруженном редакторском мире и перечень отсутствующих/противоречивых ID. Он не назначает и не исправляет ID. Ошибки missing ID у read-only/transient целей — информационные; у известных постоянных pickup/storage — блокируют приёмку. Дубликат непустого ID у разных Actor — ошибка независимо от класса; результат содержит обе ссылки. PIE-копию и editor-world не объединять в один набор.

Область гарантии — **все загруженные Actor одного мира**, включая загруженные sublevels. До приёмки authored-уровня загрузить все требуемые подуровни/cells и зафиксировать охват. Незагруженные карты/cells, DTO и глобальное пространство GUID всех inventories/стеков не проверяются. Нельзя объявить project-wide уникальность или заменить этим A36/T15. При неизвестном/неполном охвате отчёт содержит ограничение; уровень с непроверенным обязательным authored-набором не принимается.

Полный runtime scan имеет стоимость O(N) Actor с интерфейсом. Он выполняется на проверяемой команде, не на каждом tick/обновлении HUD. Кэш/реестр GUID и World Partition координатор не вводятся в ID01; при необходимости такого расширения — отдельный контракт.

## 6. Универсальная подсказка и Context

HandleInteractionFocusChanged выполняет следующую цепочку:

1. Проверить IsValid(NewFocus), затем DoesObjectImplementInterface(BPI_Interactable). При отказе безопасно скрыть focus-информацию, если HUD жив.
2. Получить актуальный Controlled Pawn и проверить его валидность. При отсутствии Pawn скрыть focus-информацию. Не читать свойства invalid/destroyed цели или Pawn.
3. Вызвать GetInteractionTargetId для NewFocus. Использовать его ID, если HasStableId и IsValidGuid; иначе использовать пустой Guid.
4. Создать FInteractionContext: Interactor = self PlayerController, Pawn = актуальный Controlled Pawn, TargetId = значение шага 3. Вызвать GetInteractionOptions интерфейсным сообщением на NewFocus.
5. При пустом массиве скрыть подсказку. Иначе сохранить текущую политику первого варианта: Enabled -> ShowPrompt; disabled -> ShowDisabledReason с существующим резервным текстом. Проверять живой HUD до обращения.

HUD не делает cast к pickup/storage, не запускает ExecuteInteraction, не генерирует ID, не меняет inventory и не выполняет дорогую проверку уникальности. Подсказка при пустом или конфликтном ID сама по себе допустима и не выдаёт разрешения на команду. Read-only GetInteractionOptions не должен требовать действительного TargetId только ради отображения prompt; проверки конкретной доступности могут возвращать disabled reason.

Сохранить существующие скрытие при потере focus, результат действия и его таймер. Не менять частоту поиска, сравнение Actor в ApplyFocus, подписки, число компонентов или input mode. Незавершённые пользовательские узлы можно использовать после сравнения графов; нельзя перезаписать весь EventGraph по DSL, потеряв несвязанные/отключённые узлы.

## 7. Изменяющие команды и A15

ID — необходимое условие, а не авторизация. Авторитетный исполнитель заново проверяет живую ссылку TargetActor, текущий Pawn/Controller, допустимый режим, актуальный focus, range/LoS, действие и доступность цели; для storage также уникальность из раздела 5. ExpectedTargetId из Context должен совпасть с текущим ID именно проверяемого Actor. Сохранённый UI Context и успешный прежний focus не дают права на будущий commit.

Текущий срез проекта — одиночная игра: авторитетная проверка исполняется игровой логикой, а не виджетом. Сетевые RPC/репликация/серверный протокол не проектируются в ID01.

- HandleWorldPickupRequest, ValidateWorldPickup, Consume/PickupInProgress, TryAddExact, порядок commit/event/destroy и сообщения результата A15 сохраняются. Добавление getter не заменяет existing ID-check в ExecuteInteraction и не добавляет второй вызов команды.
- Пустой или несовпадающий ID в непосредственном вызове ExecuteInteraction pickup должен отклоняться существующим A15 без изменения snapshot/Actor/events. Новая глобальная duplicate-защита в pickup mutation-пути не добавляется без отдельного изменения A15; authored-дубликаты выявляет аудит уровня и они блокируют приёмку.
- Для storage недействительный/дублирующийся ID запрещает любую будущую изменяющую операцию. ID01 предоставляет проверку, но не добавляет фиктивную команду, успешный Open или session-флаги. Существующий незавершённый ExecuteInteraction не превращается в production-реализацию.
- Реальную проверку storage перед commit и закрытие внешней сессии подтвердит отдельный контракт Open/Transfer. Тест одного identity-validator **не** считается интеграционным PASS хранения/переноса.

## 8. План безопасной реализации после утверждения

1. Повторно проверить ветку/HEAD/status и активный проект редактора. Зафиксировать hashes сохранённых пакетов и получить read-only snapshot текущих графов, включая отключённые узлы, defaults и связи, через MCP. Сравнить сохранённую версию в изолированной копии/отдельном процессе без reload/revert текущего редактора. Не сохранять все Unsaved пакетами. Если безопасное сравнение недоступно — остановиться до записи и точно сообщить ограничение.
2. Найти всех implementers BPI и потребителей Context; составить точный whitelist пакетов. Сделать резервные копии только затрагиваемых сохранённых файлов и снимков памяти вне публикуемых Content/Docs. Не менять чужие worktree и не переносить накопленную ветку целиком.
3. Добавить getter и реализации pickup/storage, переменную storage и read-only проверки. Явно назначить ID только согласованным экземплярам storage тестовой карты после сохранения их пользовательских настроек. Инвентари не переинициализировать.
4. Точечно переподключить HUD через MCP. HandleWorldPickupRequest оставить без рефакторинга. Компилировать интерфейс, все implementers, библиотеку и Controller; при необходимости только read-only compile зависимых ресурсов. Unsaved зависимости не сохранять автоматически.
5. Выполнить матрицу раздела 9 на точных хешах. Для trace сначала подтвердить реальный HitActor, ImpactPoint, distance и LoS в PIE. Менять collision/BPC_Interaction только при доказанном дефекте; отдельно записать причину и diff. Если изменение выходит за ID01 — CHANGE REQUIRED.
6. Сохранить только согласованные пакеты с сохранением пользовательских графов; повторно сверить графы/хеши, файлы и статус. Обновить этот отчёт и ProjectStatus фактическими PASS/FAIL/NOT RUN. Публикация запрещена без отдельной команды владельца.

Планируемый whitelist: `BPI_Interactable.uasset`, `BP_WorldPickup.uasset` (только getter), `BP_StorageContainer.uasset`, `BP_SurvivalPlayerController.uasset`, новый `Content/Survival/Interaction/BPFL_InteractionIdentity.uasset`, read-only audit-скрипт, точечные ID экземпляров в `LV_SystemsTest.umap` и документация. Изменение BPC_Interaction/другого implementer допускается только после выявления конкретной необходимости и фиксации границ; несвязанные assets не добавлять. BPC_Inventory, A11, GDD, A36 v1, Config и .uproject не входят в изменения ID01.
