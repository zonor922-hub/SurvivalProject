Generated-каталоги Saved, Intermediate и DerivedDataCache не включены. История Git не входит в эту файловую копию: снимок сделан до инициализации репозитория. Восстановить проект из неё можно без Git/LFS. Manifest и проверяющий скрипт лежат рядом с проектом, чтобы копию можно было переносить целиком вместе с проверкой.

## 2. Локальный Git + LFS

Репозиторий создан в **настоящем** `<PROJECT_ROOT>`, а не в папке документации.

| Параметр | Результат |
|---|---|
| Ветка | `main` |
| Исходный commit | `04b7b9524d4170f045712440723f2efe4b4cd313` |
| Метка | `a02-baseline-2026-10-25` |
| Отслеживаемые файлы | 781: 779 исходных + `.gitignore` + `.gitattributes` |
| LFS-файлы | 773: бинарные ресурсы Content и PNG из корня |
| Git | 2.53.0.windows.3 |
| Git LFS | 3.7.1 |
| Проверка LFS | `Git LFS fsck OK` |
| Внешний remote | Не настроен; публикации/отправки файлов не было |

Автор исходного commit — `автоматический снимок`. Он задан только для этого commit; глобальное имя/почта пользователя не менялись.

Добавлены два файла:

- `.gitattributes`: `.uasset`, `.umap`, bulk data и распространённые исходные медиа хранятся через LFS; INI/uproject/uplugin используют CRLF, соответствующие существующим файлам Windows; документация и скрипты — LF.
- `.gitignore`: исключает корневые Binaries, Saved, Intermediate, DerivedDataCache, служебные IDE-файлы. Config и весь Content остаются отслеживаемыми. Binaries сторонних плагинов не игнорируются глобально: они могут быть нужны бинарным плагинам.

Git LFS hooks и фильтры установлены локально. Удалённый сервер блокировок не настроен; атрибут `lockable` намеренно не включён, чтобы локальные ресурсы не становились read-only без рабочего lock server. При совместной работе бинарные ресурсы требуют отдельной политики владения/блокировок.

Это локальное управление версиями. Дополнительная независимая копия проекта уже находится на C:, а исходный проект и его Git — на D:. Автоматическое расписание резервного копирования не создавалось.

## 3. Проверка настоящего восстановления из Git

Создан отдельный checkout:

```text
<LOCAL_WORKSPACE>\RecoveryCheck\A02_20261025_130415\SurvivalProject
```

Применён `git clone --no-local --no-checkout`, затем локальная установка LFS и checkout исходной метки. Режим `--no-local` создаёт отдельную базу Git-объектов. Восстановление на C: из источника на D: не использует hard links между дисками.

Проверено:

- все **779 исходных файлов восстановлены байт в байт**, включая INI и `.uproject`;
- все **773 LFS-файла развёрнуты в настоящий бинарный контент**, а не остались текстовыми указателями;
- Git blob карты содержит корректный LFS pointer, его OID соответствует SHA-256 оригинального `.umap`;
- отдельный `git lfs fsck` прошёл в восстановленном checkout;
- `git check-ignore` действительно исключает тестовые пути Saved, Intermediate, DDC, Binaries и .vs;
- восстановленный checkout чист по `git status --porcelain`.


## 5. Как продолжать разработку

Работать в `<PROJECT_ROOT>`. Перед задачей проверять `git status`, после завершения проверять список изменений и сохранять отдельный commit. Не выполнять массовый `git add .`, если ещё не просмотрены новые файлы и исключения.

Примеры просмотра состояния в PowerShell:

```powershell
git -C '<PROJECT_ROOT>' status --short
git -C '<PROJECT_ROOT>' log --oneline --decorate -5
git -C '<PROJECT_ROOT>' lfs ls-files
```

Для нового commit добавлять явные пути затронутых ресурсов, конфигурации или исходников. Не переименовывать метку A02 и не переписывать исходный commit. Настройка личности пользователя для его собственных commit — отдельная пользовательская настройка; для автоматических commit указывать автора явно.

## 6. Восстановление без перезаписи оригинала

Самый простой путь — файловая копия. Запустить `verify_backup.py` рядом с manifest, убедиться в `Hash mismatches / missing: 0`, затем скопировать каталог `SurvivalProject` в **новую отсутствующую папку**, например `<PROJECT_ROOT>_Restored_A02`. Открыть её `.uproject` движком 5.8.4 и выбрать карту `Content/Content/Survival/Maps/LV_Survival_Nature`.

Если Python не установлен, для A02 проверка уже выполнена; manifest позволяет повторить её любым SHA-256 инструментом. Для восстановления не нужны Saved/DDC/Intermediate: движок создаст их заново.

Чтобы восстановить из текущего репозитория и одновременно проверить LFS, выполнять команды только с новым отсутствующим каталогом назначения:

```powershell
git clone --no-local --no-checkout '<PROJECT_ROOT>' '<PROJECT_ROOT>_Restored_From_Git'
git -C '<PROJECT_ROOT>_Restored_From_Git' lfs install --local
git -C '<PROJECT_ROOT>_Restored_From_Git' checkout --detach a02-baseline-2026-10-25
git -C '<PROJECT_ROOT>_Restored_From_Git' lfs fsck
```

Если в checkout `.umap` оказался небольшим текстом `version https://git-lfs.github.com/spec/v1`, LFS-контент не восстановлен: такой checkout нельзя считать готовым проектом. В A02 это проверено фактическим восстановлением и SHA-256. Для переноса всей истории на другой носитель нужны Git-объекты **и** LFS-объекты; один обычный git bundle не содержит LFS-файлы. Существующий RecoveryCheck уже содержит обе части для исходного commit.

Не использовать `reset --hard` или копирование поверх рабочего проекта как стандартный способ проверки восстановления. Сначала открыть независимую копию и убедиться в её содержимом.
