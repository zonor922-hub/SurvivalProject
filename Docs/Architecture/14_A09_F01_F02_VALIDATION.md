# A09 — итоговый отчёт и исправления F01/F02

27.10.2026, Europe/Moscow. Реальная версия движка: `5.8.4-58902052+++UE5+Release-5.8`.

База исправлений: main `c7f02030c99b3105bd3f5c395222155eae2dbd1e`, включающая A08 `01393c19f765440554f1ce1767112f9ae4474f1a` и A09 `616191be5aff11f4378a60532a9a3ee9b70a2532`. PR №7 уже объединён. Ветка исправлений — `fix/f01-f02-a09-validation`; старая локальная main и backup не изменяются.

## Что исправлено

**F01:** опубликованы необходимые тестовые исходники A09, временная Blueprint-фикстура обработчика события, модельный тест и runner. Временный генератор игровых графов a09_build.py и локальные Listener*.uasset не переносятся. Существующий `/Game/__A09Test/Listener` и карта не меняются: карта имеет ссылку на него, удаление не входит в задачу.

PowerShell runner запускает отдельный UnrealEditor-Cmd. Он фиксирует SHA, dirty-status и SHA256 исходных Content/Config/uproject, сохраняет результаты в новом каталоге Saved. Старый JSON не может выдать себя за новый результат: повторное использование каталога с context/summary запрещено. Частичный результат A09 сохраняется при исключении; внутренние fixture-функции удаляются в finally и компонент повторно компилируется. Тесты не сохраняют assets. После процесса runner проверяет хеши, timeout, exit code и логический итог; любой провал возвращает shell exit=1. Передача `-InjectFailureForRunnerTest` проверяет именно этот отрицательный путь.

**F02:** точечные изменения двух существующих графов:

- `PDA_ItemDefinition.ValidateDefinition`: проверка конечности UnitWeight и DurabilityMax в уже существующей активной durability-ветви. Невалидные числа дают прежние InvalidUnitWeight/InvalidDurability. Нулевой конечный вес разрешён. Неактивная DurabilityMax игнорируется согласно прежнему контракту.
- `BPC_Inventory.InitializeInventory`: finite WeightLimit вместе с прежним WeightLimit>=0. До исправления +Infinity разрешала инициализацию, теперь отказ не меняет Snapshot; последующая корректная инициализация разрешена.

В установленном KismetMathLibrary нет отдельного scalar IsFinite. Использована чистая проверка IEEE-754 `(X-X)==0`: конечное число даёт 0, NaN и обе бесконечности — NaN и false. В ValidateDefinition добавлено 10 узлов, в InitializeInventory — 3. Порядок существующих ошибок и no-op повторной успешной инициализации сохранён. Графы не пересоздавались; структуры, поля, GUID полей, enum, карта, команды и dispatcher не менялись.

GameInstance не менялся: существующий вызов ValidateDefinition теперь блокирует Ready для nonfinite данных и очищает частичный lookup. Входная активная прочность стека уже корректно отвергала NaN/±Infinity — её runtime-реализация не менялась, добавлены regression-тесты.

## Повторение из чистой копии

Требуются Unreal Engine 5.8.4, PowerShell, Git и восстановленные Git LFS assets. Скрипты Python загружаются из этого репозитория; старые рабочие копии, их untracked-файлы и установленный внешний Python не требуются. PythonScriptPlugin включается только для процесса. Редактор этой копии перед запуском закрыть, чтобы исключить ручное сохранение временных фикстур.

Из корня чистой рабочей копии:

```powershell
& './Docs/Architecture/evidence/run_f01_f02.ps1' -EngineRoot 'F:/UE_5.8'
```

A10 входит в стандартный запуск; -ExcludeA10 означает неполную приёмку. Заменить только путь установки UE. Все пути проекта вычисляются относительно runner; пробелы в пути допустимы. Итог находится в напечатанном каталоге `Saved/Verification/F01F02/<timestamp>/summary.json`, полный лог — Unreal.log. Нужны passed=true, process_exit_code=0, timed_out=false и пустой changed_source_files. При failed-case просмотреть соответствующий JSON и error, не объявлять успех по одному exit коду Unreal.

Дополнительно проверить отрицательный путь harness:

```powershell
& './Docs/Architecture/evidence/run_f01_f02.ps1' -EngineRoot 'F:/UE_5.8' -SkipSwimming -InjectFailureForRunnerTest
```

Здесь ожидаются shell exit=1 и сообщение `Intentional runner failure propagation test`. Это не обычная команда приёмки. `-SkipSwimming` явно пропускает A24, такой запуск не доказывает проверку плавания.

Результаты пишутся отдельно; исходные `a09_build.json`/`a09_verification.json` сохранены как исторические записи коммита A09, не как доказательство F01/F02. В частности, старый флаг private_guard_requires_ui_verification не отменяет новых 13 отрицательных/публичных compile-проверок.

## Диагностика и ограничения

Заметка ChangedSlots в CommitInventory остаётся. В UE 5.8.4 `DetectValuesReturnedByRef` выдаёт для массива Note о невозможности обратного возврата по ссылке. Доставка массива подписчику и точность индексов подтверждены тестами. Это уведомление, а не публичный setter; dispatcher не переделывался ради подавления заметки.

Ожидаемые compiler errors внешних тестовых Blueprint подтверждают Private-защиту. Стартовые сообщения UnifiedErrorTest в сборке движка и отсутствующие SDK нецелевых платформ не считаются провалами inventory. Полные логи сохраняются, утверждение «в логе вообще нет Error» не делается.

Новая Windows-упаковка и clone с пустым сетевым LFS-кэшем не выполнялись; чистая рабочая копия использует общий локальный object/LFS store. Headless NullRHI проверяет логику/физику, не внешний вид. F03 (ручной Listener), F04 (упаковка), F05 (vendor references/input) не включены. Производственный GameMode остаётся ThirdPerson по существующему плану A41/A42.

## Проверка пользователем и A10

1. В рабочей копии исправлений открыть «Панель ресурсов» → «Содержимое/Survival/Maps» → LV_SystemsTest; нажать «Играть», проверить ходьбу/камеру/прыжок, затем остановить.
2. Открыть PDA_ItemDefinition → ValidateDefinition → «Компилировать». У четырёх реальных DA_Item сверить прежние значения; не вводить NaN вручную и не пересохранять корректные определения.
3. По необходимости визуально проверить плавание по инструкции A24; автоматический прогон уже проверяет три берега. Не сохранять временный override GameMode на production-карте.

После приёмки и слияния F01/F02 можно начинать A10 от обновлённой main отдельной веткой. Текущий набор станет обязательной регрессией для split/merge. A10 в этой работе не начиналась. Автоматическое слияние не выполняется.
