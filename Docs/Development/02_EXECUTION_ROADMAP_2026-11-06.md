# SurvivalProject — пересмотр последовательности реализации (06.11.2026)

**Статус:** обновлённый план исполнения по утверждённым решениям; **не является** новой реализацией или самостоятельным разрешением менять Blueprint. Установлен приоритет зависимостей, а не новые игровые правила.  
**Источник статусов:** [ProjectStatus](../ProjectStatus.md), [реестр механик](../MECHANICS_TRACKER.md), [исходный backlog A01–A44](../Architecture/03_IMPLEMENTATION_BACKLOG.md). Исторические записи старых задач не переписывать.

## Причина изменения порядка

После объединения документальных PR #29, #35, #36, #38, #39 и игрового PR #37 появились/уточнены зависимости между A18–A23, Inventory UX, BP01, DEATH01, A36–A40 и BUILD01. A17 MVP (#28) и A17.1 (#37) уже опубликованы, но **новый Inventory UX и BP01 не реализованы в UE**. BUILD01 и SLEEP01 имеют утверждённые проектные решения, не runtime. Issue #30 остаётся **OPEN**, но согласованные решения не следует обсуждать заново.

## Сквозные зависимости, которые готовятся заранее

- **Архитектура данных A36 v1 и будущий v2-review начинаются аналитически уже на этапах 1–2.** Полный A37–A40 workflow реализуется, когда определены реальные сохраняемые системы; ранний design review не равен runtime SaveGame.
- **Инвентарь разбивается на малые PR**, а не задерживает весь проект до закрытия абсолютно всех будущих возможностей. Для каждого среза нужны точные валидаторы, rollback/idempotency и регрессия прежних контрактов.
- **SLEEP01:** базовый дизайн закрыт; не открывать новое обсуждение сна без реального блокера интеграции. TIME01, A20/A21/A23, BP01 и SaveVersion 2 учитываются в WP06.
- **DEATH01:** целевая потеря носимого имущества отличается от исторического A23; сначала контракт, затем отдельная реализация и migration/tests.
- **BUILD01:** внутренний порядок [WP01–WP07](../Architecture/31_BUILD01_WORK_PACKAGES.md) сохраняется без изменений: WP01 → WP02 → WP03/WP04 → WP05-A → WP06 → WP05-B → WP07. WP05-A может проектироваться раньше; полная приёмка зависит от результатов других пакетов.
- **Дизайн-гейт [Issue #30](https://github.com/zonor922-hub/SurvivalProject/issues/30):** OPEN только для реально неутверждённых деталей. Закрытые решения BP01/UX не открывать повторно; отсутствие решения тормозит только соответствующий runtime-срез.
- **Параллельно допустимы** визуальный прототип, стилизованные ассеты и изолированный schema review при отсутствии конфликтующих UE/контрактных записей. Они не подменяют системные проверки.

## Границы этого изменения

Только **очередность, навигация, реестр и актуализация статуса**. Исходный [backlog A01–A44](../Architecture/03_IMPLEMENTATION_BACKLOG.md), исходные контракты **A29–A40**, **A36 v1**, [BUILD-WP01–WP07](../Architecture/31_BUILD01_WORK_PACKAGES.md), GDD, Blueprint, карты и CI здесь не меняются. Новая последовательность **не означает старт или PASS** перечисленных задач. Для фактической реализации требуются отдельная задача, разрешение, изолированный PR и проверка в UE.

## Следующее действие

**Контрольный аудит baseline main**, после него подготовить ограниченный implementation gate **A18 (минимальный контейнер) → A19 (lifecycle)**. При обнаружении недостаточно определённого поведения оформить точечный контракт для конкретного среза, не заново весь Inventory v1.0.
